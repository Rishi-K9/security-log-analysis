# Rollback Evidence

## **Objective**
Document a rollback procedure for the Security Log Analysis project.

## **Platform**
GitHub

## **Rollback Procedure**
1. Open the project repository.
2. Select the file that needs to be restored.
3. Open the file history to identify an earlier version.
4. Review the previous content.
5. Restore the required content and commit the change.
6. Verify that the corrected file appears in the repository.

## **Evidence Status**
This document describes the rollback procedure. An actual rollback has not yet been performed.

## **Expected Outcome**
The project file can be restored to its intended content while keeping changes recorded in GitHub history.

## **Conclusion**
GitHub version history helps track changes and supports recovery from incorrect file updates.
